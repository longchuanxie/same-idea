首版设计边界

不做广告流、不做礼物商城、不做复杂社交。先把“日期准确、提醒清楚、小组件清新耐看、数据可备份”做到稳定。

清新低饱和 本地优先 农历支持 未来预览 小组件优先 Windows 轻量 年轻桌面感

年轻清新的 UI 原则

从视觉层面弱化传统工具感，让它更像一个清爽、温柔、每天都愿意看一眼的桌面日子卡片。

清爽首页

首页只展示今日、即将到来和用户置顶日子，用空气感留白和轻色块减少压迫感。

结果一眼懂

农历不解释复杂规则，直接展示“今年哪天过”和“未来几年预览”，减少理解成本。

桌面清新感

卡片使用大数字、短文案、半透明清透色，适合长期停留在手机和电脑桌面。

私密也轻松

小组件提供隐私模式：可隐藏名称，只显示“今天的纪念日”和剩余天数，不尴尬。

Android 主应用原型

左侧为可点击切换的手机原型。整体强调年轻清新、低负担录入、清楚的农历结果预览和轻量提醒。

当前原型定位：本地优先、无广告、无强制登录。云同步和家庭共享作为后续版本能力。

首页 UI 要点

一个主卡片只讲最近的今天的纪念日；列表只保留名称、日期类型、对应日期和天数。避免把首页做成万年历。

大数字清新低饱和最近优先

默认路径为“名称 → 日期 → 提醒 → 保存”。只有选择闰月、农历三十、2 月 29 日时才出现策略提示。

结果预览异常才提示不讲术语

详情页 UI 要点

详情页承担信任建立：原始日期、本年对应、未来几年预览、提醒规则必须清楚。

原始日期未来 5 年提醒清晰

设置页 UI 要点

将隐私、备份、日期显示偏好放在设置页。云同步不出现在首版主流程里。

本地备份隐私模式权限检测

核心用户流程

围绕低心智路径设计：用户只需输入日期，系统给出清楚、轻松、可信的结果和预览。

1
记录日子

输入名称，选择公历或农历日期。普通日期不出现复杂规则设置。

2
查看结果

系统展示今年对应日期和未来几年预览，替代复杂规则解释。

3
设置提醒

支持当天、提前 1/3/7 天提醒；检测通知权限并给出清晰提示。

4
放到桌面

Android 小组件和 Windows 桌面卡片持续展示，不需要频繁打开 App。

工程实现标注

UI 原型已经对应 CTO 风险判断：日期引擎、提醒、小组件刷新、备份协议需要独立模块化。

模块UI 中体现工程建议风险
农历日期新增页农历选择 + 详情页未来预览独立 CalendarEngine，保存原始农历日期，不只存公历 occurrence高
提醒权限设置页通知提醒入口Android 13+ 通知权限检测；精确提醒作为高级权限高
小组件刷新Android 2x2 / 4x2 小组件零点刷新 + 用户编辑后主动刷新 + 打开 App 校准中
Windows 组件桌面悬浮卡片与托盘形态首版 WPF/.NET 或轻量桌面方案；不优先做 Windows Widgets Board中
备份恢复设置页导入/导出JSON schema 版本化，Android 与 Windows 共用数据协议中
隐私模式小组件可隐藏名称Widget display_rule 支持 NORMAL / PRIVATE / MINIMAL低
