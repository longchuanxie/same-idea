# 农历数据源与授权边界确认记录

版本：v1.0  
确认日期：2026-06-19  
对应故事卡片：M0-CALENDAR-001 确认农历数据源与授权边界  
状态：已确认

---

## 1. 结论

首期农历能力采用“标准规则基线 + 离线内置数据表 + 独立 CalendarEngine”的方案：

1. 规则基线采用 GB/T 33661-2017《农历的编算和颁行》。
2. 运行时不调用在线农历接口，不依赖 Android、Windows 或 .NET 系统农历结果作为业务真值。
3. 首期内置规则数据文件命名为 `calendar-runtime-rules-v1.json`，规则版本命名为 `lunar-rules-1.0.0`。
4. 首期支持范围固定为 1901-01-01 至 2100-12-31。
5. 农历事件模型必须显式保存 `lunarYear`、`lunarMonth`、`lunarDay`、`isLeapMonth`。
6. 闰月不能只靠月份数字表达，序列化、Room、备份 JSON、Windows 导入和 UI 展示都必须保留闰月标记。

## 2. 权威依据

### 2.1 国家标准

国家标准全文公开平台显示：

- 标准号：GB/T 33661-2017
- 标准名称：农历的编算和颁行
- 英文名称：Calculation and promulgation of the Chinese calendar
- 标准状态：现行
- 发布日期：2017-05-12
- 实施日期：2017-09-01
- 主管部门：中国科学院
- 归口部门：中国科学院

中国科学院相关解读材料说明，该标准明确了农历计算模型、精度、编排规则和表述方法。项目以该标准作为现代中国农历业务语义的规则基线。

### 2.2 闰月表达要求

Unicode LDML 对中国农历闰月的说明指出，中国农历可能在一年中几乎任意月份之后插入闰月，闰月会沿用前一月名称并附加特殊标记。因此工程实现必须把闰月作为独立布尔标记或等价结构保存，不能只保存月份数字。

## 3. 数据来源策略

### 3.1 首选生成策略

`calendar-runtime-rules-v1.json` 应按 GB/T 33661-2017 的规则语义生成，并在生成后通过 golden 与业务场景回归测试校验。生成文件应包含：

- `version`
- `range.start`
- `range.end`
- `source`
- `checksum`
- 每个农历年的春节公历日期
- 每个农历年的闰月信息
- 每个农历月的月份、是否闰月、天数

### 3.2 开放数据交叉校验

香港天文台通过 DATA.GOV.HK 提供“Gregorian-Lunar calendar conversion table / 公历与农历对照表”，可作为公开交叉校验数据源之一。该数据集由香港天文台提供，支持 API 与年度 CSV，更新频率为 yearly。

DATA.GOV.HK 条款允许在遵守使用条款的前提下免费复用数据，并要求保留来源标识、免责声明等条件；FAQ 也说明除转售数据外，对用途没有额外限制。项目若将 DATA.GOV.HK 数据作为生成或校验输入，必须：

1. 在生成脚本和资产元数据中记录来源 URL、抓取日期和条款版本。
2. 在随包说明或第三方声明中保留 DATA.GOV.HK / Hong Kong Observatory 来源与免责声明。
3. 不转售原始数据。
4. 不把外部 API 作为运行时依赖。

### 3.3 多源核验要求

M0-CALENDAR-002 和 M0-CALENDAR-003 生成数据资产时，必须至少完成以下核验：

1. 规则结构核验：每年农历月序列、闰月、大小月合规。
2. 双向转换核验：公历转农历、农历转公历 round-trip。
3. 特殊日期核验：春节年界、除夕、闰月、农历三十、2 月 29 日。
4. 抽样交叉核验：与公开对照数据或权威历书数据抽样比对。
5. Flutter Android/Flutter Windows 解析核验：同一 JSON 被 Dart `calendar_core` 在共享测试与平台壳中解析为一致结构。

## 4. 用户提示文案

当用户输入或导入的日期超出首期支持范围时，统一返回 `OUT_OF_RANGE`，面向用户展示：

```text
当前版本支持 1901-01-01 至 2100-12-31 范围内的公历与农历日期。这个日期暂时无法计算，请选择范围内的日期。
```

技术日志可记录：

```text
Calendar date is outside supported range 1901-01-01..2100-12-31.
```
