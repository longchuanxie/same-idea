# 知识库下一程：场景与路线（2026-09 立项）

> 结论：知识库从「一次生成的分析产物集合」转向「贯穿阅读时刻的动线设施」。
> 形态跟着「时刻」走，不跟着「图表类型」走。本文档是 M1–M3 的裁定依据，动手前先读。

## 一、人格与时刻

| 人格 | 典型时刻 | 真实问题 | 现有覆盖 |
|---|---|---|---|
| 长篇网文读者（主力） | 隔几天回到在读长书 | 三分钟找回状态（主角在干嘛、和谁一伙） | 人物图谱部分覆盖；情节线空白；内容更新靠手动替换（M1.8） |
| 同上 · 重读 | 想看重头戏 | 高潮在哪一章，直接跳 | 空白 → M1 节拍结构条 |
| 技术文档读者 | 拿到陌生 SDK/协议文档 | 我从哪进入？完成任务经过哪几步？ | 空白 → M3 接口调用图 |
| 同上 · 照着做 | 读教程/手册 | 第一步干嘛、条件分支走哪边 | 空白 → M3 方法流程图 |
| 学术读者（存量人格） | 读前分流 | 这篇值不值得精读 | 论文速览卡 ✓ |
| 同上 · 读中 | 概念/方法不懂 | 术语定义、方法 pipeline | 术语卡/概念图谱 ✓、流程图 M3 |
| 同上 · 读后 | 文献综述 | 十篇摆一张桌上比较 | **空白**（方向题，Atlas 为地基，本期不做） |

判据（开工前可自查）：馆藏文本书 vs 技术类 PDF 占比；速览卡/术语卡生成量；上线后看**回原文点击率**、**节拍点击率**与**替换触发次数**（追更型读者的唯一直接证据）。信号采集为本地 localStorage 计数（`usageSignals` 服务，写入失败静默）+ 设置页「导出使用数据」，不上报——随 v1.25 先落，否则 M1/M2 验证信号悬空。

> 2026-09-24 修正：书籍自导入即静态快照——无书源、无更新检测、同标题导入即拦截。主力时刻的触发器是**读者回归**而非更新事件，产品叙事为「长书回归伴侣」；「连载每周长新章」描述的触发器在产品里不存在。内容更新由 M1.8 替换流以手动方式补上。

## 二、路线

### M1 全书骨架 digest + 叙事节拍结构条（本里程碑）

- **digest 基建**（零 API 成本的全本视野）：每章 = 标题 + 首尾逐字摘句 + 字数，总预算定死（≈7.6k 字）；超长书确定性等距采样（保首尾章）。证据摘句取自骨架原文 = 逐字可定位，回原文链路不受损。
- **节拍任务**：单块语料（digest 即唯一 chunk），注册表形状不变；一次调用产出全书节拍（开局/引子/推进/转折/中点/低谷/高潮/结局），去黑话词汇，术语降级为侧卡补充。
- **结构条落点在目录页**：目录折叠后读者丢失全局结构感，节拍尺补回来——点节拍直达该章。知识库卡片保留完整查看器入口。
- 验证信号：节拍点击率、回原文点击率。

### M1.5 生成后台运行（2026-09-24 落地，裁定依据）

长书生成动辄十几个分块、以分钟计，读者不会盯着档案卡等——**生成必须脱离页面与前台存活**，这是知识库从「功能」变「动线」的前置基建：

- **持久化队列**（`generationQueue` + DB v12 `generationTasks`）：串行并发 1（跨任务），分块 checkpoint 随进度落库；成功/取消即删，失败以 `failed` 态留档断点（不随启动自动续跑，显式重试只补未完成块）。App 被杀/刷新后启动时自动续跑，语料指纹对不上（书内容变了）自动作废重跑。
- **分块规模与并发**（2026-09-24 二次裁定）：分块数由全书字数自然决定（6k 目标块，取消原 60 块硬上限——长网文不再「只分析前 60 块」）；同书分块走 4 路滑动窗口并发（墙钟约为串行 1/4），单块流式 + 300s 超时 + 退避重试 2 次。跨块称呼一致性退为「派发瞬间快照」：同波并发块互不见新名字，靠后续派发块逐步继承。
- **前台保活**（`GenerationKeepAlive` 插件 + dataSync 前台服务）：Capacitor 的 onPause 不暂停自家 WebView，JS 本可在后台继续跑；前台服务补的是 Doze 限网与进程回收两刀。Android 通知由服务独家持有（单一通知条不叠影），终态通知 detach 留栏回看；非 Android 原生回落 local-notifications，Web 空操作。
- **executor 分层**：队列只管排队/持久化/续跑/事件，LLM 逻辑在 `generationRunner`（纯函数，checkpoint 续跑在此对齐块序）；store 负责 book 解析（书架→IDB 兜底）与覆盖式落库（续跑前必须先 loadArtifacts，否则旧件 id 不复用、产出重复件——模拟器实测抓到过）。
- 验证（模拟器实测）：入队→通知栏进度→HOME 退后台完成落库；force-stop 杀进程→重启自动续跑（通知重现 1/3 段）→完成，无重复产物。

### M1.8 书籍替换更新流（v1.25 落地，2026-09-24）

「同书换新文件」从拦截改为替换：importFile 的文件名标题/解析标题两处拦截点改弹确认（替换/保留两本/取消；漫画文件夹与档案合并流维持拦截——非文本书无替换语义），替换弹窗展示标题/作者/章节数/来源文件名对比防误伤（同标题 ≠ 同书）。替换语义：**同 bookId 换内容 blob**，进度锚天然抗尾部追加（chapterIndex + chapterTitle 四级回退，网文新章尾部追加前部索引不动），标签/收藏/入库时间保留；删该书 DB v11 章节缓存（否则开书读旧章）；旧知识件标「已过期 + 一键重跑」（stale 位，重新生成覆盖落库即随新件消失；不自动删，token 花费在册）。首发限定 TXT/MD（EPUB 运行期 object URL 不跨会话）。伴生信号采集（`usageSignals`）：回原文点击、节拍点击（BeatsView/结构条）、替换触发三事件，13 处点击点逐一埋点。

验证（浏览器实测）：同标题剪报二次入藏弹确认（2 章 vs 3 章对比 + 来源文件名）、点替换后同 bookId 原书 2→3 章不新增书目、进度保留、`book-replace` 信号 count=1 落账；亮/暗双模式弹窗截图人眼验收（与 ConfirmDialog 同形制无溢出）；挂起态不再误报「入藏失败」（剪报台/OPDS/WebDAV 三入口都对齐）；真·增量补充维持护栏外。

### M2 情节脉络线

泳道时间轴（每条情节线一行，域色板取色）+「你在这里」游标（readingProgress 现成）+ 章末卡片动线接入；digest 注入分块提示词当全书上下文，稳线归属。~~增量补充原生~~已移除（2026-09-24：触发器不存在，见 §一修正）——全书重跑由 M1.8 替换流 + 队列承担；真·增量补充（只跑新章并入现有产物）压护栏外，解封条件：替换触发率成规模 + 全书重跑成本被信号证明确实痛。

### M3 技术文档双卡 + 学术词汇微调

- 方法流程图：分层 DAG 布局（最长路径分层 + 重心序，纯函数）；操作步骤/论证链/请求管线。
- 接口调用图：复用图谱机械（节点=接口、边=调用），加方向箭头；**别名归并关**（getUser ⊄ getUserById），knownNames 开（治标识符漂移）；文案诚实限定「文中出现的调用关系」——文档不是源码，不承诺完整性。
- 学术微调：速览卡提示词按报告体换词汇（核心判断/依据/风险），**不拆新卡**（防子类型碎片化）。

### 方向题（下一阶段）

读后跨篇比较（综述矩阵/多报告对读），Atlas 为地基；等 M1 验证信号出来再立项。

## 三、护栏（不做什么）

1. 不为文档子类型拆专属卡；
2. 不承诺图谱完整性（覆盖率对账 + 限定词代替）;
3. 不动跨篇比较；
4. 验证信号出来前不给节拍条加编辑/拖拽交互；
5. 不做书源/抓取/自动更新检测（法律灰区 + 维护无底洞）；替换流纯手动，真·增量并入等信号解封。

## 四、每期固定携带「信任四件套」

回原文跳转 · 覆盖率对账 · 修订模式 · Markdown 导出——相对通用 AI 工具的唯一差异化，验收项而非后续补课。
