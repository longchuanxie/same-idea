## 〇、核心概念：「一座活的私人图书馆」

**一句话定位**：Kuro Reader 不是一款「看书工具」，而是一座**只属于你、不断生长的私人图书馆**——它记得你读到哪里（记忆），书架随你的阅读而变化（生长），有纸、墨与灯光的温度（体温），每个功能都能落在一个图书馆意象上（隐喻一致性）。

四根体验支柱：

| 支柱 | 含义 | 主要落点 |
|---|---|---|
| **记忆** | 图书馆记得一切：进度、偏好、批注、静置时长 | 书签动线、批注锚点、书的生命状态 |
| **生长** | 馆藏与阅读痕迹随时间累积可见 | 摘抄墙、年轮热力图、入藏时间线 |
| **体温** | 纸木材质与暖光，而非冷灰工具感 | 色彩（纸白×墨黑×琥珀光×朱砂印）、材质 |
| **隐喻一致** | 每个功能都有图书馆身份，认知零翻译 | 14 页身份映射表（第六章） |

**总纲克制原则**（贯穿全文，防止过度拟物）：

> **隐喻服务于认知与情感，不增加任何操作步数。**
> 每一处拟物设计都附带克制规则；任何与可用性冲突的隐喻，可用性胜。

**人文质感红线**（凌驾于一切风格与工程决策，任何 Phase 不可妥协）：

> 这是一座「人」的图书馆，不是一台「机器」的书柜。系统化（组件收敛、协议统一、数据展示）永远不许悄悄磨掉人味。六条红线与验收检查表见 **2.10 人文质感保障**，文案语气库见 **7.8**。

1. **衬线是馆的声音**——内容性文字（书名/标题/引文/问候/大数字）一律衬线优先；无衬线只服务操作，等宽只做数据标点。
2. **文案有体温**——面向用户的一切文案走图书馆语气，禁止系统腔（「操作成功」「错误 401」「暂无数据」）。
3. **机器退后**——编号、百分比、状态码永远降为辅助层级，叙事文字才是主层级。
4. **手作痕迹**——保留恰到好处的不完美（印章微旋、纸纹微噪、缎带毛边），拒绝像素级完美对称的「生成感」。
5. **人的痕迹可见**——批注、划线、进度、静置天数是「馆藏记忆」，永远有处可看。
6. **留白即尊重**——圣域区（阅读正文/座位卡/摘抄卡）留白只增不减。

## 一、现状诊断总览

### 1.1 产品与技术底座

- 技术栈：React 18 + TypeScript + Vite + Tailwind CSS 3.4 + Zustand + React Router 6 + Capacitor 8（Android 为主，兼顾 Web）；IndexedDB 本地存储；Vitest 测试 206 个全绿。
- 产品定位（ROADMAP.md）：本地优先 + NAS 自托管的漫画与文字统一阅读器；批注（稳定锚点 + Markdown 导出）、标签、搜索、Markdown/KaTeX/Mermaid 渲染能力，是向知识库演化的现成地基。
- 现有视觉基础：「Kuro」单色文学风（黑白灰 + 暖白底 + 衬线字体），token 纪律在核心组件上相当好（TopAppBar/BottomNavBar/ConfirmDialog 100% 语义类）——这是本次重构可以站住的底子。**问题不在「花」，而在「轻、散、冷、假」四个字**（见 1.2C）。

#### C. 视觉气质问题（「轻、散、冷、假」）

1. **轻**——形状语言过轻：`rounded-full` 胶囊全项目 149 处（悬浮胶囊底栏、胶囊按钮、圆形 chips）。「悬浮 dock + 胶囊」是消费级轻快的语言，与「图书馆」的分量感相悖。
2. **散**——中英文字体气质分裂：`font-display` 配置为 `['Playfair Display','serif']`（tailwind.config.js:71），拉丁字母用 Playfair，**中文直接回退系统默认衬线**，标题中英混排时风格不稳定；UI 标签 `['Inter','sans-serif']` 同样没有中文字体位。
3. **冷**——底色 `#fdf8f8` 是**偏粉**的暖白（R 通道偏高），大面积铺开后呈「胭脂灰」，既不纸也不墨；暗色 `#111111` 是纯冷黑。整座「图书馆」没有一处暖光。
4. **假**——层级靠 1px 描边撑：卡片普遍 `border border-outline-variant` 平铺在同一底色上，五级 surface 容器色相邻档差仅 2~3%，视觉上近于「线框稿」，缺乏「纸叠起来」的真实层级。
5. 魔数失控：图标字号 arbitrary 类 96 处（`text-[18px]`×32、`text-[20px]`×22、`text-[24px]`×15、`text-[16px]`×16）；按钮内边距约 10 种组合无常量（`px-4 py-3`×32、`px-6 py-2`×23…）。
6. token 双源：tailwind.config.js:7-69 与 index.css:38-78 同值重复定义，且 Tailwind 的 `dark:` 变体机制实际未用，运行时全靠 CSS 变量——改一处颜色要改两处，必漂移。

## 二、设计语言：「活图书馆」体系

### 2.1 概念

把现有「怯懦的单色工具」升级为「有身份的私人图书馆」。视觉四要素一句话：**墨**（文字与主色）、**纸**（底与卡片）、**光**（琥珀色的暖与生命）、**印**（朱砂藏书印——全 app 唯一强调色）。

这个方向同时回应三个诉求：

- **大胆、艺术表达性**——朱砂印、衬线铭牌、打字机体编目号，都是强个性元素；
- **沉稳的底子**——大面积仍是纸白与墨黑，个性只出现在「点」上；
- **知识库演化**——图书馆隐喻天然容纳分类（标签=分类目录）、笔记（批注=手记）、检索（搜索=检索台）、统计（台账）。

### 2.2 色彩：墨 · 纸 · 光 · 印

#### 浅色模式（日光阅览）

| 令牌 | 值 | 用途 |
|---|---|---|
| `paper`（background） | `#F7F4EE` | 全局底色。米白纸色，去粉调、保留米暖 |
| `paper-raised`（container-lowest） | `#FCFAF6` | 浮起的第一层纸（对话框、菜单底） |
| `surface-1`（container-low） | `#F1EDE5` | 卡片、sheet 底 |
| `surface-2`（container） | `#EAE5DB` | 次级容器、输入框底 |
| `surface-3`（container-high） | `#E2DCD0` | 按压态、嵌套容器 |
| `surface-4`（container-highest） | `#D9D2C4` | hover 态、禁用底 |
| `ink`（primary / on-background） | `#211E1B` | 主文字、主按钮底（暖墨黑，替代纯黑） |
| `ink-soft`（on-surface-variant） | `#5C574F` | 次级文字 |
| `ink-faint` | `#8A8478` | 辅助文字、占位 |
| `line`（outline） | `#B9B2A4` | 强分割线 |
| `line-soft`（outline-variant） | `#D8D2C5` | 弱分割线、卡片描边（降频使用，见 2.6） |
| `wood` | `#8C6F4E` | 木质：桌面侧边栏底、书架线（仅结构性元素） |
| `wood-deep` | `#6B5438` | 木质按压/深线条 |
| `lamp`（琥珀光） | `#C8963E` | 今日之灯、光效、次强调（低频） |
| **`seal`（藏书印·唯一强调色）** | **`#BC4529`** | 激活态、进度、批注高亮、链接、印章、关键数字 |
| `seal-deep` | `#9A3420` | seal 按压态 |
| `seal-soft`（container） | `#F3DED4` | 选中容器底、批注底色（浅） |
| `error` | `#B3261E` | 破坏性操作（与 seal 同族但更冷更深，见克制规则） |

#### 暗色模式（夜读的图书馆）

| 令牌 | 值 | 说明 |
|---|---|---|
| `paper` | `#191714` | **暖黑**（带棕调），替代现在的冷黑 `#111111` |
| `paper-raised` | `#201D19` / `surface-1..4` | `#262320` `#2C2823` `#343028` `#3D382E` |
| `ink` | `#EDE7DB` | 暖白前景（激活/主文字反转为浅） |
| `ink-soft` / `ink-faint` | `#B5AD9E` / `#807A6D` | |
| `line` / `line-soft` | `#4A443A` / `#3A352D` | |
| `wood` | `#241F19` | 夜里木质退为深棕面板色 |
| `lamp` | `#D9AE5F` | 夜读灯光反而更亮一档（一盏灯的感觉） |
| `seal` | `#D0604A` | 朱砂提亮以保对比度（≥4.5:1 on paper） |

#### 色彩克制规则

1. `seal` 是**唯一**强调色：任何「想用彩色」的场合先问能不能用 ink/seal 解决。单屏 seal 面积 < 5%。
2. `lamp` 只用于「生命力机制」（今日之灯、阅读中的炉火），不做交互色。
3. `wood/wood-deep` 只用于**结构性元素**（桌面侧边栏、书架分割线），禁止用于按钮和文字。
4. `error` 与 `seal` 同为红色族：破坏性操作**必须**同时携带图标+文字（如「删除」），永不单靠颜色区分。
5. 每个颜色的可读性门槛：正文对比度 ≥ 4.5:1；`seal` 用于小字号文字时须 ≥ 4.5:1（暗色下提亮即为此）。

### 2.3 材质

| 材质 | 实现 | 用途 | 克制规则 |
|---|---|---|---|
| **纸** | 现有 6 种纸张纹理（`src/utils/paperTexture.ts`：宣纸/牛皮纸/墨水屏…）从「阅读器专属」升格为**全局材质令牌**：`texture-strength` 0–100 | 全局底（默认极淡 8%）、卡片可选 | 纹理强度用户可调；列表/网格等密集区默认关纹理保性能 |
| **木** | 纯色 `wood` + 1px 木纹线（`repeating-linear-gradient` 极淡条纹） | 桌面侧边栏、书库「书架横板」分割线 | 移动端不用大面积木色，仅书架线 |
| **黄铜** | `lamp` 色 1px 线条，`border-image` 或伪元素 | 重点分割线、桌面侧边栏激活指示条 | 每屏至多 2 处 |

### 2.4 字体：四角色

| 角色 | 字体栈 | 用途 |
|---|---|---|
| `font-display` 铭牌 | `'Playfair Display', 'Noto Serif SC', serif`（自托管，w600/700） | 页面大标题、书名、统计大数字 |
| `font-body` 正文 | `'Literata', 'Noto Serif SC', serif` | 正文阅读、书籍摘要 |
| `font-label` 索引卡 | `'Inter', 'Noto Sans SC', sans-serif`（**新增自托管 Noto Sans SC**，w400/500/600） | 全部 UI 标签、按钮、列表元信息 |
| `font-mono` 编目号（**新增**） | `'IBM Plex Mono', 'Noto Sans SC', monospace` | 编目号、时间戳、页码 `x/y`、百分比、版本号——「借书卡的机械感」 |

要点：

- **补齐中文字体位是本次字体工作的核心**：现状中文全部回退系统字体，衬线铭牌与无衬线索引的中英气质分裂（1.2C-2）。Noto Serif SC / Noto Sans SC 自托管并按常用字重子集化（约 +180KB woff2，可用 `font-display: swap` 消除闪烁）。
- 字号阶梯沿用现有 M3 式命名（tailwind.config.js:75-85 纪律良好），**新增 `display-xl`（56/64，w700）** 用于门厅问候语与归架仪式；`label-sm` 保留 12px 但拉丁字符加 `letter-spacing: 0.08em`，呈索引卡排印感。
- 编目号场景统一 `font-mono text-label-sm`：如 `KR-C-0042`（书籍 ID）、`82%`、`12/38`。这是成本最低的「图书馆气质」来源。
- **等宽字是「标点」不是「声音」**：单屏等宽文本 ≤3 处、禁用于整句，避免「机器面板感」（详见 2.10-1）。

### 2.5 形状母题

| 母题 | 定义 | 用途 | 克制规则 |
|---|---|---|---|
| **纸片圆角** | `rounded-card 6px`、`rounded-card-lg 10px`（输入框/对话框 6px） | 所有卡片、面板 | 胶囊形（full）仅保留三类：头像、圆形图标钮、开关 |
| **书签切角** | 右下 45° 切角（`clip-path` 8×8px） | 主按钮、选中态 chip、「继续阅读」大卡 | 每元素至多一处；只用于可交互元素 |
| **书脊线** | 左侧 3px 竖条（ink 或 seal） | 列表视图的书目行、侧边栏激活项 | 仅一处/元素 |
| **印章圆** | 圆形描边 + 内文字（旋转 -8°） | 「已入藏」印章、归架仪式、封面无图占位 | 见 2.8-3 |

### 2.6 层级与阴影：纸的叠放

放弃「一切靠 1px 描边」，改为**表面色阶为主、阴影为辅、描边为补**：

| 层 | 表达 | 用途 |
|---|---|---|
| L0 底 | `paper`（+可选纹理） | 页面 |
| L1 纸片 | `surface-1` + `shadow-paper` | 卡片 |
| L2 浮纸 | `paper-raised` + `shadow-paper-up` | 菜单、弹出卡 |
| L3 器物 | `paper-raised` + `shadow-raised` + 顶部 1px 高光 | 对话框、sheet、底栏（浮起时） |
| 弱分割 | `line-soft` 1px | 仅同层内的列表分隔（书架线） |

阴影令牌（暖色调阴影，不用纯黑）：

```

shadow-paper-up:  0 4px 16px rgba(33,30,27,.10)
shadow-raised:    0 8px 32px rgba(33,30,27,.14)
/* 暗色模式追加顶部高光 border-top: 1px solid rgba(237,231,219,.06) */
```

### 2.7 动效：纸的物理 + 生命体征

| 令牌 | 值 | 用途 |
|---|---|---|
| `motion-instant` | 120ms `ease-out` | 按压、hover、开关 |
| `motion-flow` | 200ms `cubic-bezier(.2,0,0,1)` | 面板进出、抽屉、页面转场 |
| `motion-ritual` | 480ms `cubic-bezier(.34,1.3,.64,1)`（轻微过冲） | 印章、归架、贴墙——仪式瞬间 |
| `motion-breathe` | 4s `ease-in-out` 循环 | 灯光/炉火微动（装饰级） |

规则：所有 `motion-breathe` 尊重 `prefers-reduced-motion: reduce` 与全局「动效」设置；仪式动效点击可跳过。

### 2.8 生命力机制（「活」从哪来）

#### 1. 书的生命状态

每本书在书架上呈现四种「姿态」，用**角标 + 一行小字**表达，不用彩色标签：

| 状态 | 表达 | 附加文案 |
|---|---|---|
| 摊开（在读） | 封面右侧挂进度丝带（书签缎带，seal 色，长度=进度%） | 「第 12 章 · 82%」 |
| 插签（中断） | 脊上丝带图标 | 静置 >7 天时显示「已静置 N 天」 |
| 竖立（未读） | 无角标 | — |
| 归架（读完） | 脊上小印点（seal） | 「已归架」 |

克制规则：状态 = 1 图标 + ≤1 行小字；「已静置 N 天」仅在 >7 天且未读完时出现，且不做任何红点/数字角标打扰。

#### 2. 图书馆的呼吸

- **今日之灯**（首页）：每日阅读目标渲染为一盏灯，进度 0→100% 灯芯由暗到亮（`lamp` 色辉光半径渐大）。目标本身沿用现有每日目标数据（`useStatsStore`）。
- **年轮热力图**（统计）：热力图五档色阶由灰绿「苔藓」改为 **ink→seal 的墨→朱砂阶**，隐喻「读得越勤、印得越红」。
- **炉火**（阅读器）：阅读界面底部的极轻微暖光呼吸（`motion-breathe`，透明度 ±2%）——**默认关闭**，设置中开启。

#### 3. 仪式瞬间

- **入藏印**：导入成功时，结果卡上书封处盖一枚旋转 -8° 的「入藏」朱砂圆印（480ms 缩放落下 + 轻微墨晕），随后出现「立即开读」。
- **归架仪式**：读完全书（进度达 100% 或最后一章结束确认）→ 全屏短暂 480ms：书脊归架动效 + 「已归架」印 + 累计阅读时长 + 「下一本推荐」（同标签/同作者未读优先）。
- **贴墙**：批注保存成功时，浮起提示「已贴入摘抄墙」，首页/手记的摘抄墙 +1。

克制规则：每类仪式在同一会话内**第二次起跳过动效**只留结果；仪式绝阻断操作（点击即跳过）。

#### 4. 时间的表达

- 门厅问候按阅读时段变化：晨读（5-11）/ 午后（11-17）/ 掌灯（17-23）/ 夜读（23-5），问候语衬线大字 + 对应光色微调（夜读时门厅灯光元素更亮）。
- 空态是「活的」：空书架不说「暂无数据」，说「**书架还空着——从采编台带回第一本书吧**」并给直达按钮。

克制规则：问候语一天内最多变化 4 次、无动画；时间表达不进入阅读器（阅读中永远无打扰）。

### 2.10 人文质感保障（验收红线）

重构最大的风险不是「不够大胆」，而是在系统化过程中（组件收敛、协议统一、数据展示）悄悄变成一台冷机器。以下六项保障与〇章红线对应，是每期验收的硬标准。

#### 1. 字有风骨（字体层级的人文分工）

| 角色 | 承担 | 禁止 |
|---|---|---|
| 衬线（display/body） | 全部「表达」：书名、标题、引文、问候、仪式文案、统计大数字 | — |
| 无衬线（label） | 全部「操作」：按钮、菜单、表单、导航 | 承担内容表达 |
| 等宽（mono） | 仅四类数据标点：编目号 / 时间戳 / 页码 / 百分比 | 用于句子；单屏 >3 处 |

#### 2. 文案有体温

示例对照（完整语气库见 7.8）：

| 机器腔（禁止） | 图书馆腔（采用） |
|---|---|
| 操作成功 | 已入藏 |
| 删除成功 | 《三体》已移出特藏室（撤销） |
| 暂无数据 | 书架还空着——从采编台带回第一本书吧 |
| 确认删除？ | 把《三体》从馆中移除？它的 12 条手记也会一并消失。 |
| 网络错误 | 这家合作馆暂时没有回应 |

#### 3. 数字叙事化

统计数字永远不裸奔：大数字必须跟一行**叙事小字**，把数据翻译成人的经验，由数据模板自动生成（不手写、不虚构）：

- ✗ `1,240 分钟` → ✓ `共读 1,240 分钟——大约 21 个安静的夜晚`
- ✗ `连续 5 天` → ✓ `连续 5 天开馆有你`

叙事小字用衬线或 ink-soft 小号，紧随数字；模板见 6.10。

#### 4. 密度分区：圣域与工具间

| 分区 | 覆盖 | 密度规则 |
|---|---|---|
| 圣域 | 阅读器正文、门厅座位卡、摘抄卡、问候区 | 行高 ≥1.7、外边距 ≥24px、禁弹层打断；**留白只增不减** |
| 街区 | 书架网格、档案卡、台账卡 | 现状密度保持，卡片间距 ≥16px |
| 工具间 | 批量条、设置面板、表单、采编进度 | 允许紧凑，但文案仍走图书馆语气 |

任何页面不得整页都是工具间；工具间文案必须能通过 7.8 语气库。

#### 5. 手作痕迹清单（允许的不完美）

| 痕迹 | 实现 |
|---|---|
| 印章微旋 | -8° 基准，每次盖章 ±3° 随机偏移 |
| 纸纹微噪 | feTurbulence 噪点分布不均（现有纹理即符合） |
| 缎带毛边 | 进度丝带末端 1px 锯齿（CSS clip 微缺口） |
| 手写落款（可选） | 摘抄墙落款可选手写楷体（如霞鹜文楷），默认关闭 |

原则：每屏手作痕迹 ≤2 处；痕迹是「被使用过」的证据，不是装饰贴纸。

#### 6. 人文质感检查表（每 Phase 验收必过）

- [ ] 随机截一屏：衬线是否承担了主表达？等宽是否 ≤3 处？
- [ ] 该屏全部文案是否通过 7.8 语气库？有无系统腔残留？
- [ ] 大数字是否都有叙事小字伴随？
- [ ] 是否仍有功能只能靠 hover/隐藏手势触达？（0 容忍）
- [ ] 圣域区留白是否 ≥ 现状？
- [ ] 手作痕迹是否 ≤2 处/屏（防过度拟物）？

## 四、交互动线设计

> 本章与视觉同级，是重构的另一半。先立全局模型与返回协议，再逐条走六条核心动线。

### 4.1 全局动线模型：「进馆动线」

```
        门厅 Home ──── 你的座位 / 今日之灯 / 摘抄墙
           │
     书库 Library ─── 书架（网格/列表）· 特藏室 · 分类目录
        │  │  │
        │  │  └─ 采编台 Import ── 馆际借阅 CustomCloud（合作馆）
        │  └─ 检索台 Search ── 历史记录 / 分类筛选
        └─ 书籍档案卡 BookDetail ── 档案 / 目录 / 标签 / 手记
                    │
              阅览室 Reader / TextReader ── 阅读 · 批注 · 书签
                    │
              台账 Stats ── 年轮热力图 · 借阅统计
```

动线设计三原则：

1. **任何高频动线 ≤2 步**：从门厅到「继续读上一本」= 1 点击；从任何页到检索 = 顶栏常驻。
2. **动线有来有回**：每条支线终点都能一步回主干（顶栏返回 + 统一返回协议）。
3. **阅读器是圣域**：进入阅览室后一切动线让位于「读」，其他入口全部收进可呼出 chrome。

### 4.2 浮层层级与统一返回协议

#### 层级表（z-index 分层，自上而下消费）

| 层 | 内容 | z-index | 返回键行为 |
|---|---|---|---|
| 1 | Toast / UndoToast | z-70 | 不消费返回键，自动消失 |
| 2 | Dialog（确认/表单弹窗） | z-60 | 关闭弹窗 |
| 3 | BottomSheet（阅读设置等） | z-50 | 收起 sheet |
| 4 | Drawer（章节抽屉/侧栏/批注列表） | z-40 | 关抽屉 |
| 5 | Menu / Popover | z-30 | 关菜单（**统一点击外部关闭**，修复 Library 排序菜单不关闭） |
| 6 | 行内编辑模式 | — | 取消编辑（含未保存确认） |
| 7 | 阅读器 chrome 显隐 | — | 先显 chrome |
| 8 | 页面 | — | `navigate(-1)`（历史栈底则退出 app） |

#### 统一返回协议（修复 1.2D-3）

- **一个服务收口**：扩展现有 `src/services/backHandler.ts` 为三层同源——Android `backButton`（现有）、**Web `popstate` 拦截（新增）**、键盘 `Escape`（新增，从各页面硬编码 `navigate(-1)` 迁移）。三者都按上表**从上往下找第一个活动层消费**。
- 修复点：
  - TextReader `Escape` 直接退页（`TextReader/index.tsx:1433`）→ 改走协议；
  - Reader 同类问题（`Reader/index.tsx:1059-1060`）；
  - SubLibrary 返回键（`SubLibrary/index.tsx:140` 的 `navigate(ROUTES.LIBRARY)`）→ 标准化 `navigate(-1)`，深链进入时 fallback 到书库；
  - SubLibrary 删除模态、Tags 原生 confirm 等不再响应返回键的浮层 → 全部换自定义组件后自动纳入协议。
- 实现方式：Dialog/Sheet/Drawer/Menu 基类组件挂载时自注册 backHandler（后注册先消费），页面无需手写。

### 4.3 六条核心动线

---

#### 动线一：采编动线（导入 → 上架 → 开读）

**现状链路**：
```
Import 选文件 → 进度卡(读取10%→解析60%→存库100%) → 成功卡
   ├─「查看详情」→ BookDetail →（再找）「立即阅读」→ 阅览室   ← 2 次跳转
   └─「去书架」→ Library → 点封面 → BookDetail → 「立即阅读」  ← 3 次跳转
CustomCloud 下载 → 成功卡「开始阅读」直达阅览室              ← 行为不一致
```

**摩擦点**：① 成功后到开读最多 3 跳（Import:281-330 无「立即开读」，CustomCloud:342-363 却有）；② 超限/格式错**静默失败**（Import:71-73、162-164 直接 return）；③ 文件夹导入可能产出「子书库」而非一本书，结果与预期错配且子库入口在书库页分组里不明显；④ 原生端单选（Import:141 `multiple:false`）。

**重构后**：
```
采编台选件 → 「编目中…」进度卡（含每册编号 i/N，font-mono）
   → 成功卡：书封 + 盖「入藏」印（仪式）+ 编目号
       ├─「立即开读」（seal 主按钮，直达阅览室）      ← 1 跳
       ├─「查看档案」（次按钮）
       └─ 多本导入：「全部开读第一本」/「去书架看看新书角」
失败卡：明确原因（超限/格式不支持/解析失败）+ 重试
文件夹导入：先展示「识别结果预览」——「将创建 1 本书 · 12 章」或
           「将创建特藏室『文件夹名』 · N 本」，用户确认后再入库
```

**验收要点**：任何导入失败必须有可见反馈；成功卡主按钮永远是「立即开读」；文件夹导入结果可预期。

---

#### 动线二：书签动线（中断 → 恢复 → 读完）

**现状链路**：
```
阅读中翻页 → saveTextProgress(章节+页+百分比+偏好) → IndexedDB
下次 → 首页「继续阅读」卡 → 直达阅览室对应章 → 自动恢复位置 ✓
卡片右上 ×（hover-only）→ removeContinueReading → 【清空该书全部进度！】
读完（percentage=100%）→ 卡片消失 → 无任何引导
```

**摩擦点**：① × 按钮 hover-only 且**无确认无撤销**地清进度（Home:39-47 → store:759-765）；② BookDetail「继续阅读」按钮有进度数据但不展示「读到第 N 章 · N%」上下文（BookDetail:94-102,349）；③ 读完即静默消失，无「下一本」引导。

**重构后**：
```
门厅「你的座位」：摊开的书大卡（书脊进度丝带 + 「昨晚读到 第12章 · 82%」）
   └─ 点击书封任意处 = 继续阅读（整卡可点，无需 hover 出按钮）
   └─ 卡片菜单（右上 ⋯，常显）→「不再显示」（仅移出座位，进度保留，可撤销 5s）
读至末章确认 → 归架仪式（480ms）→「已归架」+ 本书累计时长
   →「下一本」推荐（同分类未读优先）/「写一条手记」（引到批注墙）
```

**验收要点**：移除座位卡永不清进度；读完有仪式与出口；BookDetail 与门厅的进度上下文一致。

#### 动线三：手记动线（批注创作 → 回顾 → 馆外聚合）★知识库核心

**现状链路**：
```
创建：选中文字（长按500ms/拖选）→ 浮动「批注」钮 → AnnotationPopup
      （预览→样式三选→笔记 textarea）→ 保存（笔记为空不可存=不支持纯高亮）
回顾（阅读中）：调出 chrome → 顶栏设置图标 → 设置面板 → 滚到第 16 组「工具」
      →「批注列表」→ 抽屉（可编辑/滑删/导出MD/点击回跳原文 ✓ 跨章也能回跳）
回顾（书内）：点击正文 mark → AnnotationDetailModal —— 只读，无编辑/删除/跳转
回顾（书外）：BookDetail「导出批注」（无批注时原生 alert）—— 只能导出，无法浏览
```

**摩擦点**：① 批注列表入口在设置面板**第 16 组**，深达 4 层；② mark 点击弹窗只读（AnnotationDetailModal 无编辑/删除）；③ 书外没有批注浏览页，跨书聚合完全缺席——**这是与「知识库」距离最远的一环，也是最高价值改点**；④ 纯高亮不允许保存（note 空禁用），与「划线摘录」的轻量习惯冲突。

**重构后**：
```
创作（不变骨架，降低门槛）：
  选中 → 浮钮分两个：「划线」（零输入，直接保存纯高亮）/「批注」（弹笔记）
回顾：
  阅览室顶栏常驻「手记」图标（书签/批注合入口）→ 底部抽屉（书内全部，含编辑/删除/回跳）
  点击正文 mark → 详情弹窗（可编辑/删除/回跳原文）
聚合：
  BookDetail 新增「手记」区块：全书批注墙（引文卡列表，点击回跳原文）
  手记 tab（新增，Phase 5）：跨书「摘抄墙」——按时间倒序的全部划线与批注，
     按书分组、按标签过滤，支持导出 MD、搜索
  归架仪式的「写一条手记」直接落到这里
```

**验收要点**：从任何位置到批注列表 ≤2 步；每条批注都能一键回跳原文；跨书聚合可检索。

#### 动线四：书务动线（长按管理 → 批量操作）

**现状链路**：卡片 hover → 三图标钮（收藏/编辑/删除）（Library:604-632）；「管理」→ 多选模式 → 底部浮动胶囊条（与底栏 z-50 叠放，Library:681-739）；多选时筛选条消失（Library:504）。

**摩擦点**：触屏不可达（1.2A）；多选模式与浏览模式互斥过度（筛选被禁用）；两个浮动条叠放。

**重构后**：
```
任意书卡 → 长按 500ms → 情境菜单（bottom sheet）：
   继续阅读 / 编辑档案 / 收藏切换 / 移入特藏室 / 删除（seal 文字，二次确认）
   菜单底部「选择多本」→ 进入多选
多选模式：顶栏变形为「已选 N · 全选 · 取消」，批量操作移到顶栏
   （不再与底栏叠放）；筛选条保持可用
桌面端（lg+）：hover 快捷图标保留，作为鼠标用户加速器（非唯一路径）
```

**验收要点**：全部书务操作触屏 1 长按可达；多选中仍可筛选；单浮层。

#### 动线五：调阅动线（阅读器设置）

**现状链路**：漫画——长按正文呼出设置（Reader:862-871，**无提示**）；文本——chrome 底栏设置图标 → 单列 17 组滚屏（TextReaderBottomBar:126-596，maxHeight calc(100vh-220px)）。

**摩擦点**：入口一隐一显不一致；17 组平铺，最常用的主题/字号排在第 4、10 位；「工具」（书签/批注/收藏）这类**导航型**按钮混在开关中间；两个阅读器面板结构完全不同。

**重构后**：
```
统一 chrome：点正文中央呼出 → 顶栏（返回|书名全名|目录|手记|收藏|设置）+ 底栏
设置面板 = 三 tab bottom sheet：
  [排版] 字号 · 行距 · 字体 · 对齐 · 首行缩进 · 竖排        ← 高频
  [外观] 阅读主题 · 纸张与纹理 · 亮度 · 色温
  [更多] 阅读模式 · 点击翻页区 · 章末连读 · 自动滚动速度 · 双页/方向（漫画）
「手记」从面板中移除，升为顶栏常驻
首次进入阅读器：一次性 coach 提示「点按中央呼出菜单 · 长按快速设置」（可跳过）
```

**验收要点**：常用项 ≤1 滚屏内可见；两阅览室 tab 结构一致；无隐藏手势。

#### 动线六：寻书动线（检索与探索）

**现状链路**：顶栏搜索 → Search 即时过滤（标题/作者/分类/标签）→ 行列表；「最近添加」藏在 Search 页（Search:152-187）；统计双入口；/tags 无入口。

**摩擦点**：检索台与「发现」混在一页；无搜索历史；分类目录（标签页）不可达；统计入口重复且与底栏高亮不符。

**重构后**：
```

  结果行：封面缩略 + 书名 + 一行元信息（作者·分类·进度状态）
分类目录：桌面侧边栏常驻「分类」区；移动端书库页头部「分类」入口
  → Tags 页（入口归位）：8 色分类色 + 关联书目数 + 展开看书
统计（台账）：入口收敛为「门厅今日之灯点击 + 桌面侧边栏」，
  移动端暂保留顶栏图表 icon，删除「更多」菜单里的重复项
```

**验收要点**：/tags 至少两个常驻入口；统计入口唯一化后底栏高亮不再失真；搜索历史可管理。

### 6.3 SubLibrary —— 特藏室

**身份**：馆内按主题开辟的专室。现有 grayscale 封面恰好是「特藏档案感」——**保留并命名这个意图**。

**改版要点**：
1. grayscale 保留为特藏室专属语言，页头加一句定位文案「特藏室 · 入藏于此的书」；hover/长按菜单恢复彩色预览。
2. 返回键标准化 `navigate(-1)`（修复 SubLibrary:140），删除模态纳入返回协议。

### 6.4 Search —— 检索台

**身份**：馆前的检索台：一台打字机式的查询框、一排分类抽屉、一叠检索结果卡。

**改版要点**：
1. 搜索框升级为检索台样式（底部下划线 → `surface-2` 纸片框 + mono 占位符「检索书名 / 作者 / 分类…」）。
2. **搜索历史**：最近 8 条 chips（本地存储，可清空）；无输入时展示历史 + 热门分类。
3. 修复条件：「最近添加」移出门厅迁入的重复（该区块整体迁至 Home，见 6.1），检索台只做检索——修正 `!query.trim()` 判断（Search:152）残留的展示逻辑随迁移一并删除。
4. 结果行增加状态徽记（在读 ┃ / 已归架 ✓）与 mono 进度，点击保持进 BookDetail。
5. 结果排序：按相关度（标题命中 > 作者 > 分类），无结果时引导「去采编」。

### 6.5 Import —— 采编台

**身份**：新书入馆的采编台：编目、盖章、上架。

**改版要点**：
1. 布局重构为**两条通道卡**：「本地采编」（选择文件 / 从文件夹）与「馆际借阅」（→ CustomCloud），卡片视觉对等但主行动明确。

## 七、组件规范

### 7.1 Button（收敛 21 处重复模式）

| variant | 样式 | 用途 |
|---|---|---|
| `primary` | ink 底 / paper 字 / 书签切角 | 常规主行动 |
| `accent` | **seal 底 / paper 字** / 切角 | 每屏至多 1 个：立即开读、继续阅读 |
| `secondary` | surface-1 底 + line-soft 边 | 次行动 |
| `ghost` | 透明 + ink 字 | 三级行动、取消 |
| `destructive` | ghost/secondary + seal 文字 + delete 图标 | 删除（ConfirmDialog 内可 seal 实底） |

尺寸 `sm/md/lg`（3.2）；按压 = `surface-3` 替换或 4% 变暗（motion-instant）；禁用 = `surface-2` + `ink-faint`。**禁止 opacity 悬浮反馈以外的自造样式。**

### 7.2 反馈与浮层组件

- **Dialog**：`paper-raised` + `rounded-card` + `shadow-raised`；标题衬线；主右次左；destructive 见上。替代全部原生 `alert/confirm`（替换清单：Settings:102-105,137、Tags:54、BookDetail:367、Settings:807）。
- **BottomSheet**：grabber 圆条 + `max-height 70vh` + `motion-flow`；承载设置面板/情境菜单/表单。
- **Toast / UndoToast**：底栏上方浮出（`bg-ink text-paper`，z-70）；危险操作附带「撤销 5s」；替代原生 alert 的非阻断场景。
- **Menu**：`paper-raised` + `shadow-paper-up` + **统一点击外部/返回键关闭**（useDismiss hook），收敛 Library:351-404 与 TopAppBar:36-45 两套行为。

### 7.3 InlineEdit 统一范式

铅笔 icon → 字段行内替换（宽度不变）→ ✓ 保存 / ✗ 取消；Enter 提交、Esc 取消；离开且未保存 → Toast「已放弃修改」（或确认）。替换三处自造范式（BookDetail:140-201 / SubLibrary:152-155 / Tags:90-151）。

### 7.4 母题组件（新）

| 组件 | 说明 |
|---|---|
| `SealStamp` | 入藏/归架印章：圆形描边 + 两字（入藏/归架）+ 旋转 -8° + motion-ritual 落章 |
| `RibbonProgress` | 书脊进度丝带：seal 缎带，高度=进度%，卡片右上角 |
| `LifeStateBadge` | 生命状态角标（摊开/插签/竖立/归架，2.8-1）+ 静置文案逻辑 |
| `ShelfLine` | 木质书架分割线（移动端书库/特藏室） |
| `CatalogChip` | 分类 chip：色点 + 名称；选中 = ink 底 + 切角 |

### 7.5 图标与触达

- Material Symbols Outlined 保留（FILL 切换习惯好，BottomNavBar:68）；新增规则：图标尺寸只用三档 utilities（16/20/24），收编 96 处 arbitrary。
- 触达：点击区 ≥44px；书卡整卡可点；`hover:` 仅作桌面加速器，**任何功能不得只存在于 hover 态**。

### 7.6 空态规范（活空态）

结构：一句图书馆语气文案 + 一个主行动按钮。示例见 2.8-4；替换 Home:137-147（「悬停收藏」）、Library/SubLibrary/Tags/Search 空态。禁止裸图标 + 「暂无数据」。

### 7.7 进度与加载规范

- 确定进度：mono 百分比 + 条（导入/下载/同步）；
- 不确定进度：骨架屏（沿用 index.css shimmer）；
- 行内操作：按钮内 spinner（保存中）；
- 阅读进度：丝带（卡片）/ 细条 2px（列表）/ 滑杆（阅读器）。

### 7.8 文案规范（图书馆语气库）

语气总则：**拟人，不卖萌**。像一位安静的老馆长——少字、具象动词、说清后果。禁用语气词（哦/啦/~/鸭）、感叹号与技术术语直出（参数/缓存/句柄/401）。

| 场景 | 模板 | 示例 |
|---|---|---|
| 主按钮 | 动词 + 宾语（不加「请」） | 继续阅读 · 带回一本书 · 立即开读 |
| 破坏性确认 | 把《X》…？+ **后果一句** + [移除] [留下] | 把《三体》从馆中移除？它的 12 条手记与进度会一并消失。 |
| 常规确认 | 将…？+ 影响一句话 | 将《深空回响》移入「学术」特藏室？ |
| 成功 Toast | 结果 +（撤销） | 《三体》已入藏 · 立即开读 ／ 已移出座位（撤销） |
| 空态·书库 | 场景 + 一个出口 | 书架还空着——从采编台带回第一本书吧 [去采编] |
| 空态·手记 | 价值召唤 | 还没有手记。读的时候，长按一句话就能把它贴上墙。 |
| 空态·搜索 | 同情 + 建议 | 没找到「量子」——馆里暂时没有，或换个短一点的词。 |
| 错误·导入 | 人话原因 + 重试 | 这本《星旅.cbz》打不开——文件可能不完整。重试 ／ 换一本 |
| 错误·网络 | 拟物归因（技术细节入括号） | 这家合作馆暂时没有回应（WebDAV 连接超时） |
| 仪式·入藏 | 一句短句 | 已入藏 · 编目 KR-0042 |
| 仪式·归架 | 时间感 + 手记回望 | 《三体》归架了。陪伴你 21 个夜晚，留下 12 条手记。 |
| 问候 | 时段 + 呼应在读 | 晚安。昨晚你在读—— |
| 静置提醒 | 轻提醒、不指责 | 《银河系》在架上静置 23 天了 |
| 设置说明 | 一句人话讲清关系 | 纸张纹理：给整个 app 一点纸的颗粒感（阅览室里的阅读纸型单独设置） |

规则：

1. 书名一律用《》；数字用 mono；动词优先馆内词（带回/入藏/归架/贴墙/移出/静置），**不造生词**；
2. 破坏性操作必须写明「会一并消失什么」；
3. 错误文案先给人话原因，技术细节放括号或「详情」；
4. 中文全角标点；按钮文案 ≤6 字；Toast ≤1 行；
5. 本表是种子库，实施时在 `src/constants/copy.ts` 集中管理，新文案须先入库存审。
